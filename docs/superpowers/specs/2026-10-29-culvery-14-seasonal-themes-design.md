# Culvery Plan 14: Seasonal themes, Halloween first

Brainstormed with the user on 2026-10-29. Halloween must be on the tablet, finished, before 31 October 2026. Visual choices stay provisional for the end-of-v1 design review, but Halloween has to look done on the 31st.

## 1. Intent

A seasonal theme dresses up the wall tablet for a time of year. It changes the tablet only: never lights, plugs, speakers or anything else in the house. Halloween is the first theme. Christmas and others follow later by adding a theme, not by reworking this one.

Success on 31 October: the wall looks like Halloween from across the room, everything the family reads is as readable as on any other day, and the doorbell plays a haunted organ.

### Goals
- A theme switches itself on and off by its dates, which are set in Settings. A preview button in Settings is the only way to show a theme outside its dates.
- Halloween restyles the whole app's colours, adds a few drawn touches on Home, swaps the Culvery mark for a pumpkin, sets the big Home clock in a Halloween face, and brings its own doorbell sound.
- The doorbell sound can be chosen in Settings › Door. It follows the theme by default.

### Non-goals
- No house devices are touched (Hue, Sonos, plugs, Home Assistant). Party mode and Holiday mode are unchanged.
- No Christmas theme in this plan. The structure must make it an addition only.
- No downloaded sound. No change to the launcher icon.
- No new readability rules. The 4d contrast rules apply as they are.

### Anti-goals (a failure even if it works)
- Anything the family reads becomes harder to read: event titles, times, the date, weather, the night clock, warnings.
- The night clock lights up the bedroom-dark room more than it does today.
- Warning red becomes easy to mistake for the Halloween orange.
- The drifting bats keep the screen or CPU busy while the tablet is dark or asleep, or make the tablet run warm.

## 2. Decisions (the user's)

1. **Switching:** automatic, by date only. Each theme has its own date range, set in Settings. Halloween defaults to 24–31 October inclusive, with the normal look back on 1 November. Settings › Display has a **Preview on/off** button per theme; that is the only way to show a theme by hand. There is no *Off* or *on now* choice (revised 2026-10-29 after the first draft).
2. **How far:** full dress (option C):
   - The Halloween colours throughout.
   - The Culvery mark in the rail is replaced by a pumpkin. No witch's hat, and no extra pumpkin by the clock.
   - A cobweb in the Today card's top-right corner.
   - A moon and a few bats in Home's background, the bats drifting slowly.
   - The big Home clock's digits in **Creepster**.
3. **Font:** Creepster (SIL Open Font Licence 1.1). Download it from Google Fonts' own repository (github.com/google/fonts, `ofl/creepster/`) with its `OFL.txt`. Check the licence file says OFL before committing, and commit it as `core/ui/licenses/OFL-Creepster.txt` next to `OFL-DMSans.txt`. The user approved this download on 2026-10-29.
4. **Daytime:** Halloween has its own day version. It switches between day and night at sunrise and sunset as today, and the Day/Night preview in the status bar works as it does now.
5. **Night clock:** unchanged in every theme: dim grey, DM Sans, same size.
6. **Doorbell:** a haunted organ playing the opening of Bach's Toccata and Fugue in D minor (out of copyright), generated by our own script like today's chime. No downloads.
7. **Doorbell setting:** Settings › Door gets "Doorbell sound": *Follow the theme* (the default: the organ while Halloween is showing, the classic chime otherwise), *Classic chime*, *Haunted organ*. Quiet hours, the chime volume setting, the tablet's notification volume and Do Not Disturb all apply as today.
8. **Delivery:** staged. Stage 1 goes on the tablet first: the colours, the pumpkin, the Creepster clock, the cobweb, moon and bats, the organ with Settings › Door's choice, and the preview button. Stage 2 follows: editing the dates and the "Next:" line. Halloween's default dates already include today, so stage 1 shows Halloween on the wall without stage 2.

## 3. Calls I made (the user agreed to these in the playback)

- The theme's colours apply on every screen (tabs, sheets, door card, PIN pad, toasts, Settings, setup wizard), because they all draw from the shared `HhColors`. The drawn touches appear only on Home and in the rail's mark.
- The bats stop moving when the screen is dark or asleep, when Home isn't showing, and when Android's "Remove animations" (animator duration scale 0) is on. In that case they are drawn still.
- Warning red (`danger`) moves towards a pinker red in both Halloween versions so it stays clearly apart from the orange. It must pass the same contrast checks as today's red.
- Person colours don't change.
- A preview ends when it's turned off or at the next local midnight, whichever comes first, so the tablet can't stay themed by accident. It isn't stored across a restart. To skip a theme for a year, change its dates; there is no separate "never show" switch.
- The preview and the dates sit behind the same PIN as the rest of Settings › Display. The doorbell sound sits behind the same PIN as the rest of Settings › Door.
- A new theme later (for example Christmas) is added as: a colour set for day and night, its drawn touches, an optional clock face, an optional doorbell sound, and default dates. Nothing else changes.

## 4. How it works

### 4.1 Which theme is showing
- A theme is a value (for example an enum `SeasonalTheme { HALLOWEEN }`, with "no theme" as null or a `NONE` entry; the builder decides). Each theme carries its default month-day range.
- The showing theme is the previewed theme while a preview is on; otherwise it's the one whose range contains today's local date. Ranges are month-days, so they repeat every year. A range may wrap the new year (for example 20 Dec – 2 Jan), and the code must handle that, though Halloween doesn't wrap. If two ranges overlap, the first theme in the list wins. That can't happen with one theme, but the rule stops it being undefined.
- The change happens at local midnight without a restart. On 24 October at 00:00 the colours fade in (the theme already animates colour changes over 400 ms). On 1 November at 00:00 they fade out. Since the night clock is showing at that hour, the change is invisible until morning anyway, and the night clock doesn't change at all.
- Each theme's dates are stored with the display's other settings (`DisplaySettings`, DataStore, `display_settings`). Edited dates are stored per theme. A stored date that is missing or can't be read falls back to the theme's default.

### 4.2 Colours
- `CulveryTheme` takes the showing theme alongside `dark` and picks (`Theme.kt:33` is the one place sets are chosen; light-or-dark elsewhere comes from `bg`'s luminance, which the Halloween values keep) one of four colour sets: normal day, normal night, Halloween day, Halloween night. Nothing below the theme needs to know which theme is showing, except the drawn touches (4.3), the clock face (4.4) and the doorbell (4.6).
- Starting values from the mockups (provisional; the builder adjusts any value that fails a check):

| token | Halloween night | Halloween day |
|---|---|---|
| bg | #120E15 | #F3ECE3 |
| surf | #1D1722 | #FFFDF9 |
| surf2 | #29212F | #F1E8DD |
| surf3 | derive, a step above surf2 | derive, a step below surf2 |
| line | #221B27 | #E3D7C9 |
| ink | #F3EEF4 | #1E1622 |
| mute | #A69AAD | #5E5263 |
| accent | #F28C28 | #A84B0A |
| accentInk | #1A0C02 | white or near-white, whichever passes |
| accentSoft | #3B2414 | #F6DCC4 |
| accentOnInk | the other version's accent, as today | the other version's accent, as today |
| danger / dangerSoft / dangerInk | pinker red, checked | pinker red, checked |
| weather, rain | as normal night | as normal day |
| border | transparent, as normal night | as normal day's border rule |

- **Contrast:** every pairing that is checked today for the normal sets is checked for both Halloween sets, by the same tests (extend the existing contrast tests to loop over all four sets rather than adding new rules). Also add a check that `danger` and `accent` differ clearly from each other in both Halloween sets. Use a hue difference or a minimum colour distance, whichever fits the existing test helpers; the builder picks the measure and the threshold, and records it.
- Screenshot tests: add Halloween day and night versions of Home, plus at least one sheet and the door card, next to the existing screenshots.

### 4.3 Drawn touches (Home and the rail only)
- **Pumpkin mark:** in the rail, replacing `CulveryMark` while Halloween is showing, at the same size and position. It is drawn as a vector in code (as `CulveryMark` is), in orange with a green stem and dark carved face. It stays a picture only, skipped by TalkBack, as the mark is today.
- **Cobweb:** a thin-line cobweb in the Today card's top-right corner (the card is `capability/calendar/.../ui/TodayCard.kt`, so the calendar module reads the showing theme through the same core seam as Door, 4.6), in a colour just above the card's surface. It sits behind the card's content and never under the "+" or "See the week" buttons' touch areas in a way that changes them. The mockup moves the "+" left to clear it. The builder decides whether that's needed at real size, but the buttons stay where they are if the web can sit behind them.
- **Moon and bats:** drawn behind Home's content (behind the header and cards, above the background colour), low contrast against `bg` so they never compete with text: a moon near the top right, behind the weather area, and three to five small bats. The bats drift slowly, roughly a screen width every minute or two, wrapping around. The drift is a Compose infinite animation tied to Home being on screen and the screen being awake (see 3, Calls). The moon and bats must not sit behind text at a contrast that changes any text's measured contrast. Text sits on cards, which are opaque, and the header text sits on `bg`, so keep the bats out of the header text's band or faint enough not to matter. The builder checks this on the screenshot.
- All drawings are our own vector paths in code. No images, no downloads.

### 4.4 The clock face
- The big Home clock's digits use Creepster while Halloween is showing. Its size and position stay as they are, and its height must not push the header's layout (the clock uses `Modifier.lineBox`; the builder checks Creepster's line box and adjusts so the header doesn't jump when the theme changes). Width matters too: the header's weather items take the width the clock leaves (`HomeScreen.kt:73`), so the clock's width must not change from minute to minute. Use tabular digits if Creepster has them, or give each digit a fixed-width slot. The colon and digits read clearly at the tablet's size. The digits are in the theme's `accent` (as the mockup) or `ink`; the builder picks whichever passes contrast at the clock's size and looks right on the screenshot.
- The date under the clock, the night clock, and every other text stay in DM Sans.
- Bundle the font as `core/ui/src/main/res/font/creepster.ttf`. It's small, so subsetting to digits and ":" is allowed but not required.

### 4.5 Settings › Display: Seasonal theme
- A new section "Seasonal themes" listing each theme with a **Preview** on/off control (stage 1), using the page's existing components and words style (sentence case, curly quotes, plain words). While a preview is on, the row says it ends at midnight.
- Stage 2: each theme's dates on its row: "Halloween: 24 Oct – 31 Oct", tappable to change the start and end day with the app's existing date or day pickers, plus a way to put the defaults back. The builder finds the existing picker that fits. Reject an end before the start unless it's a wrap across the new year, and say why in plain words.
- Stage 2: when no theme is in its dates, a line says which theme comes next and when (for example "Next: Halloween from 24 October"). This is my call; it's cheap and tells the user the dates work.

### 4.6 The doorbell sound
- `tools/sound/` gets a script for the organ (same style as `door_chime.py`: standard library only, writes `capability/door/src/main/res/raw/door_organ.wav`, 22.05 kHz 16-bit mono). Base it on the brainstorm prototype: additive organ partials, notes A5 G5 A5, then G5 F5 E5 D5 C#5 D5, about 3.6 s. Tune it for the tablet's small speaker. The prototype's lowest partial (half the note frequency) will mostly vanish there, so lean on the 2nd–4th harmonics, and keep it clearly audible at the default chime volume. Play once, not twice; the classic chime's "rings twice" ruling was for a short ding-dong.
- `Chime.play` gains which sound to play, or the chime takes a sound resource. The Door capability decides the sound from Settings › Door's "Doorbell sound" and, for *Follow the theme*, from the theme showing now. The Door module must not depend on the app module. The showing theme reaches it through `core` (for example a small `ShowingTheme` flow in `core/ui` or `core/plugin`, provided by the app). The builder picks the seam.
- Settings › Door: "Doorbell sound" with *Follow the theme*, *Classic chime*, *Haunted organ*. The page's existing "Play chime" button (`DoorSettingsPage.kt`, `door_play_chime`) plays the sound chosen. `Chime` is a `fun interface` today, so Door's test fakes change with it. Stored with Door's other settings. Unknown or missing stored values read as *Follow the theme*.

## 5. Constraints and house rules
- Branch `plan-14-seasonal-themes` in the one `culvery` checkout (no worktrees). Plain-sentence commits, no trailers. Never push without asking, and check for personal data first.
- No personal data in logs or committed files.
- No deprecated APIs without asking the user. Flag any that come up.
- Test gate: `./gradlew testDebugUnitTest verifyRoborazziDebug`.
- Subagents use `C:/t9` for scratch (short path; Robolectric's paths break past MAX_PATH).
- On the tablet: install with `install -r`, never uninstall or wipe. No Hue, Sonos or plug changes.
- Time: on the tablet by 30 October 2026 if possible, so the 24–31 October range is already showing and the user can check it in daylight and at night before the 31st.
